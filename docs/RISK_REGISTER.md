## Capability audit (2026-11-16)

- App commands (`run_ytdlp`, `cancel_ytdlp`, `binary_status`, `list_installed_browsers`, `sweep_stale_temp`,
  `editor_probe`, `edit_video`, `cancel_edit`, `editor_capabilities`) need no permission: `src-tauri/build.rs` is
  plain `tauri_build::build()` with no app manifest, and Tauri 2.12.5 (`webview/mod.rs`) checks the ACL for a
  local-origin app command only when an app manifest exists.
- `keepsake-media` is registered only on mobile (`#[cfg(mobile)]` in `lib.rs`); all 16 entries of its `build.rs`
  `COMMANDS` (including `register_listener`/`remove_listener`) are granted in `mobile.json` and its
  `permissions/default.toml`. The desktop UI never calls the plugin (`openFile` uses it only on Android or for
  `content://` paths).
- `fs:allow-read`/`allow-seek`/`allow-fstat` exist in tauri-plugin-fs 2.7.1 (`permissions/autogenerated/commands`)
  and take no scope; they act on a handle from `open`, whose path is checked against `fs:scope` plus files the
  dialog plugin adds at runtime (`try_fs_scope().allow_file`). So the "tight scope" is the existing one: no `**`
  or `$HOME` was added.
- `core:app:allow-exit` is not granted on purpose (see A9).
